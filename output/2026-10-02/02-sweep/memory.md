Confirmed Developments:
- GitHub announced on 25 Sep 2026 that agentic autofix, its security-alert fixing agent, now consults Copilot Memory and saves each new fix pattern as a memory. The stored patterns are also shared with Copilot code review and the Copilot cloud agent. Both autofix and Copilot Memory remain in public preview. Memory is on by default for individual plans and needs admin enablement in organisations, and unused entries expire after 28 days (source: https://github.blog/changelog/2026-09-25-agentic-autofix-now-uses-copilot-memory, Sep 2026) (source: https://devops.com/githubs-security-autofix-agent-now-remembers-what-it-fixed/, Sep 2026)
- Microsoft launched a rebuilt Copilot on 25 Sep 2026 with Home, Code and Autopilot. Autopilot is described as a digital teammate that lives in the customer tenant with its own identity and workspace, with permissions, audit and governance via Agent 365. It is in private preview expanding at month-end, and the launch material does not set out how its memory is stored, retained or deleted (source: https://blogs.microsoft.com/blog/2026/09/25/introducing-the-new-copilot-with-home-code-and-autopilot/, Sep 2026) (source: https://venturebeat.com/technology/microsoft-revamps-its-copilot-ai-with-a-persistent-autopilot-agent-and-hosting-for-ai-generated-apps, Sep 2026)

Emerging Signals:
- Microsoft's own admin documentation for Copilot memory (page dated 2 Sep 2026, preview) states that Purview retention policies do not apply to memory, that deleting a chat does not delete saved memories generated from it, that memory actions create no Purview audit entries, and that admins cannot restrict what is added to memory. The 24 Sep 2026 message-center notice implies the retention gap is about to close, which would make Microsoft the first major vendor to give enterprise compliance teams versioned retention of assistant memory (source: https://learn.microsoft.com/en-us/microsoft-365/copilot/copilot-personalization-memory, Sep 2026)
- Always-on agents are making persistence the default: OpenAI's Dots (DevDay, 29 Sep 2026) is reported to keep working between conversations, and one outlet says that when an app is disconnected, information already absorbed into a dot's context is not automatically removed. That detail rests on a single outlet and OpenAI's own pages were not opened (source: https://techgenyz.com/openai-dots-always-on-agents-working-conversation/, Sep 2026)
- Security press is converging on memory poisoning as an enterprise control category, citing OWASP's 2026 agentic Top 10 entry "Memory & Context Poisoning" and Microsoft's February 2026 count of 50 memory-influence attempts across industries. This is a trade-press roundup and adds no new incident (source: https://www.analyticsinsight.net/artificial-intelligence/why-ai-agents-need-cybersecurity-memory-to-protect-enterprise-data, Oct 2026)

Counter-Signals:
- Meta's Muse let two developers export large parts of its per-user virtual machine filesystem (reported 24 Sep 2026). Meta says it is not a breach, that only the user's own environment and implementation files were reachable, and that it is "continuing to adjust" what users can retrieve. This is the nearest thing to a memory-store exposure in the window and it falls short of the ledger's incident thresholds (source: https://www.macobserver.com/news/meta-muse-export-virtual-machine-filesystem/, Sep 2026)
- Governance of memory is still thinner than its spread: per Microsoft's documentation, a tenant admin cannot restrict what enters Copilot memory, memory actions are not audit-logged, and deletion of a chat leaves saved memories in place. GitHub's memory controls rely on expiry (28 days) and per-user or per-repository switches rather than audit trails (source: https://learn.microsoft.com/en-us/microsoft-365/copilot/copilot-personalization-memory, Sep 2026)

Technical Changes:
- Microsoft Purview Data Lifecycle Management will retain inactive versions of Microsoft 365 Copilot memory (saved memories, details inferred from chat history, custom instructions) when items are updated or deleted, accessible through eDiscovery. The message-center notice of 24 Sep 2026 says rollout starts late September and completes by mid-October 2026, and the roadmap entry 569612 is listed as in development, general availability, September 2026. Both pages are mirrors of Microsoft's message center and Microsoft's own pages were not opened (source: https://mc.merill.net/message/MC1478965, Sep 2026) (source: https://mc.merill.net/message/RM569612, Sep 2026)
- GitHub Copilot Memory now has a second writer in the security pipeline: repository-level facts (shared with users who have repository access, validated against the current branch, with code citations) and user-level preferences are both written by agentic autofix. Repository owners can view and delete facts in Settings > Copilot > Memory (source: https://note.com/aitrendlab/n/n49954a7f19e5?hl=en, Sep 2026) (source: https://docs.github.com/en/copilot/concepts/agents/copilot-memory, Sep 2026)

Contradictions:
- Microsoft's documentation (2 Sep 2026) says memory has no retention policy coverage and no audit entries, while the 24 Sep 2026 notice says retention is rolling out. The two are consistent only if the doc page lags the rollout, so the Learn page is not yet a reliable statement of current behaviour.
- Vendors market memory as user-controlled (views, edits, deletes) while Microsoft's and OpenAI's documentation both state that deleting a chat does not delete the memory made from it. Retention-for-compliance (Microsoft) and deletion-for-privacy remain different goals that the same feature must serve.
- Unverified, not used: Siri AI personal-context privacy coverage on MSN, the Verge's Copilot piece, Betanews on Dots and TechRepublic's Copilot piece could not be opened (HTTP 403, fetch blocked or empty), and handsontek's Purview page returned 403. No negative is inferred from them.
