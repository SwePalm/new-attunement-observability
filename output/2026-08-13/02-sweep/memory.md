# Evidence sweep, memory, 2026-08-13

Delta Since Last Sweep:
- The previous sweep ran on 2026-08-04, nine days ago, and the window is thin. One materially new development landed in it: on 6 Aug 2026 AWS published a High severity advisory against the memory tools in its own agent framework, moving memory tenancy isolation failures from a startup memory layer (mem0's OpenMemory, CVE-2026-59705, Jul 2026) to a major cloud vendor's shipped agent tooling.
- No assistant memory product movement in the window. Anthropic's Claude Apps release notes carry a single August entry (6 Aug 2026, skill and plugin security scanning) and none of the platform release note entries dated 5, 7, 10 or 11 Aug 2026 touches memory.
- No movement on the mechanism behind memory-2026-08-03. The Model Context Protocol releases list still ends at the 2026-07-28 stable specification and no memory or persistence extension is listed, so the direction of travel is unchanged from this run's grading pass.
- Two items the 2026-08-04 sweep missed, both predating it: the Strands elasticsearch_memory credential disclosure advisory (15 Jul 2026), and Anthropic's Dreams research preview for Claude Managed Agents (6 May 2026), which reads a memory store alongside past session transcripts and emits a reorganised store with duplicates merged and stale entries replaced. Dreams places server-side memory reorganisation at Anthropic roughly a month before OpenAI's consumer "dreaming" of 4 Jun 2026, reversing the ordering the previous sweep implied.

Confirmed Developments:
- AWS published GHSA-mpxq-953j-42m4 (CVE-2026-19111, High, CVSS v3.1 8.1, CWE-639) on 6 Aug 2026 against strands-agents-tools before 0.8.3, patched in 0.8.3: the mongodb_memory, elasticsearch_memory and mem0_memory tools used a namespace field as the sole tenant isolation key for every record, list, retrieve and delete operation, and exposed that namespace to the model as a tool schema parameter, so a malicious user could read, list or delete another tenant's memories, or inject false memories into another tenant's namespace to poison its future agent context, with connection parameters also exposed so the memory layer could be redirected to an actor specified cluster (source: https://github.com/strands-agents/tools/security/advisories/GHSA-mpxq-953j-42m4, Aug 2026) (source: https://services.nvd.nist.gov/rest/json/cves/2.0?keywordSearch=mem0, Aug 2026)

Emerging Signals:
- Memory exfiltration is being demonstrated as a complete chain rather than a primitive. Tencent Zhuque Lab published "Memory Heist" on 5 Aug 2026: a page serves benign content to browsers and an injected payload to agents, disguises the payload as a Cloudflare verification step, and forces the agent to encode stored memory character by character into URL paths, so the data arrives in the attacker's HTTP request logs rather than in any response body. The lab reconstructed a 37 character set API key in local validation and maps the finding to OWASP ASI06 (source: https://matrix.tencent.com/en/2026/08/06/ai-agent-memory-heist, Aug 2026)
- Memory poisoning papers now ship a defence alongside the attack, which was not true of MemGhost. GhostWriter reports roughly 98% injection and 60% activation rates against contemporary agents and proposes Agentic Memory Sentry, a memory saving policy plus a memory retrieval screen (source: https://arxiv.org/abs/2607.06595, Jul 2026). FARMA poisons the reasoning traces an agent remembers rather than the facts, and pairs the attack with a five layer defence (source: https://arxiv.org/abs/2607.05029, Jul 2026)

Counter-Signals:
- Memory layer defects are being catalogued but not exploited in the wild. CISA added nine CVEs to the Known Exploited Vulnerabilities catalog between 3 and 11 Aug 2026 (N-able N-central twice, IBM Langflow, Apache Tomcat, JetBrains TeamCity, Progress LoadMaster, Cisco Secure Firewall ASA and FTD, Microsoft Windows Ancillary Function Driver, Metabase) and none is a memory layer component. The only LLM framework among them, IBM Langflow (CVE-2026-9198), is an unauthenticated code injection giving remote code execution, unrelated to memory (source: https://www.cisa.gov/sites/default/files/feeds/known_exploited_vulnerabilities.json, Aug 2026)
- The actor that shipped the memory tenancy fix is not a memory layer vendor. The three affected tools are wrappers around Mem0, MongoDB Atlas and Elasticsearch, and the defect sat in the wrapper's namespace handling rather than in any memory store product, so the risk locus for memory isolation sits with the agent framework rather than with the memory vendors the ledger currently names (source: https://github.com/strands-agents/tools/security/advisories/GHSA-mpxq-953j-42m4, Aug 2026)

Technical Changes:
- Anthropic extended the Claude Compliance API twice inside the window, to Cowork sessions started on claude.ai web and mobile (3 Aug 2026) and to Cowork and Claude Code sessions running on users' own machines (11 Aug 2026), both in beta for Enterprise organisations under the existing read:compliance_user_data scope. The Compliance API content documentation covers chats, files, projects and session transcripts and contains no reference to agent memory stores (source: https://platform.claude.com/docs/en/release-notes/overview, Aug 2026)
- The Model Context Protocol releases list still ends at the 2026-07-28 stable specification, with no later release and no memory, state or persistence extension listed (source: https://github.com/modelcontextprotocol/modelcontextprotocol/releases, Aug 2026)
- Query time memory construction was published as a counterweight to write time synthesis. LazyMem preserves raw interactions and defers compression to query time using a 4B model, reporting 0.85 LLM judge accuracy on LongMemEval using 213 answer context memory tokens, 21.0 times fewer than its strongest non-oracle baseline, and transfer to LoCoMo without domain specific training (source: https://arxiv.org/abs/2607.22690, Jul 2026)

Contradictions:
- Tenant isolation for agent memory was enforced by a parameter the model itself could set. The namespace was simultaneously the sole authorisation key and a model controllable tool input, so the isolation boundary sat inside the untrusted surface it was meant to bound.
- Anthropic's enterprise compliance surface is reaching further into durable records while memory stays outside it. Session transcripts on employees' own machines became retrievable on 11 Aug 2026, and agent memory stores remain absent from the Compliance API entirely.
- Vendors document a confirmation step before a memory is written but not what happens to it afterwards. Microsoft documents that Copilot asks before saving, and Anthropic documents 30 day back end deletion for conversations, while neither Anthropic's retention documentation (updated 1 Jul 2026) nor Microsoft's Copilot memory page states any retention period, expiry, or source attribution for memory entries.
- The 2026-08-04 sweep treated memory portability as productised, and it is, but only as prose. Claude's documented export flow asks the model to print memory as text for the user to copy, and the same page calls memory import experimental and in active development, so the shipped portability control is a copy and paste convention rather than a format.
